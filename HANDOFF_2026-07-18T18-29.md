## ASKUE Archive Contract

- Historical ASKUE export must treat the `askue.net` server as the source of
  truth, not previously saved local CSV files.
- The current archive scope is `2026-01-01` through `2026-07-19` inclusive.
- Export must run day-by-day, then merge all daily results into one final CSV.
- Final archive deduplication key is `point_id + interval_start_local`; for
  canonical UTC rows the equivalent key is `point_id + timestamp`.
- Local files under `tmp\` are working artifacts only and may overlap if the
  same range is exported more than once.
- Canonical persisted rows in PostgreSQL do not duplicate the same source
  interval because `site_consumption_readings` uses primary key
  `(site_id, source, point_id, timestamp)` with `INSERT ... ON CONFLICT DO
  UPDATE`.
- The browser monitoring endpoint `POST /meter/{point_id}.html` may require
  runtime session cookies such as `askue` and `cf_clearance`; these are runtime
  credentials only and must never be committed, logged, or copied into system
  documents.
- The current collector/export logic separates:
  - raw `/profile` values from ASKUE JSON;
  - site/web-display values computed as `raw * value_multiplier`;
  - canonical interval energy computed as
    `raw * value_multiplier * interval_seconds / 3600`.
- `/points.scale` must remain an audit/orientation field and must not replace
  `value_multiplier` as the physical conversion factor.
