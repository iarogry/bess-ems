Назви збережено в написанні користувача. Місто, координати, ліміти приєднання й склад обладнання не визначалися за адресою.

`Sites:Catalog` задає збережений у конфігурації перелік. Під час запуску він завантажується до ISiteRegistry. `GET /sites` повертає ідентифікатори, назви й часові пояси. Ідентифікатори обов’язкові та унікальні без урахування регістру. Поки не задано джерела, площадки не мають активів, лічильників, приєднань і увімкнених інструментів оптимізації.

`Dashboard:Sites` показує всі сім адрес у режимі «Усі площадки». Для перших шести Sources порожні; відсутні потужності відображаються прочерком, статус — «Джерела не прив’язані». Новобудов 6 має наявні прив’язки, наведені нижче. `Dashboard:MembershipConfirmed=false` залишає підсумки прихованими до узгодження складу джерел і спільних установок.

Шаблон конфігурації: `config/examples/site-catalog.json`. На сервері відповідні ключі збережені в конфігурації контейнера та у захищеному settings.json. Перезапуск відновлює перелік; API створення або редагування через браузер не додано.

Користувач підтвердив 2026-10-09: «Хлібозавод 5» — це «Новобудов 6». Додано сьому площадку з цією назвою та збережено історичний SiteId `site-khlibzavod-5`. ASKUE-акаунт khlibzavod5 продовжує записувати дані під тим самим ідентифікатором; історія не переносилася. У дашборді відновлено наявні джерела цієї площадки: Deye PV/УЗЕ/навантаження і КГУ Telecontrol 5552. Старий недоступний placeholder kgu-929-realtime не додано як окремий генератор: лічильник ASKUE не є додатковим фізичним агрегатом. Його облікові дані залишаються в ASKUE. Загальний підсумок залишається заблокованим, відповідність FusionSolar ще не задана. Інші шість адрес лишаються без джерел.

Наступний крок — для кожної адреси вказати акаунт ASKUE, точки обліку та їхні ролі, Deye/FusionSolar установки, КГУ й УЗЕ, обравши одне основне джерело для кожного фізичного компонента. Команди керування залишаються вимкненими.
